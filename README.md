# 客户自动采集 · Codex Skill

员工在 Codex 输入国家、城市、客户类型或定向产品需求，自动完成公开资料研究、主体核验、联系归属、历史查重和 Excel 导出。

当前版本：**1.6.0**。按国家→城市／地区→批发市场／批发城→场内商户逐层采集，完成当前市场后才进入下一市场。独立商户经营主营且通过主体、地域、角色、联系和去重要求即可采集；白牌只作已核／待核标记。官方品牌店和专卖店同表分类采集，纯品牌方排除。

默认主营：**智能眼镜、智能手表、智能手表表带、智能手环、智能戒指**。**蓝牙耳机、蓝牙音响为附带拓展**，仅同渠道顺带保留，不占主营合格指标。员工每次明确指定一类或多类时，按专项需求执行。

## 员工安装

在 Codex 粘贴：

```text
使用 $skill-installer 从这个 GitHub 仓库安装 skills/customer-development：
https://github.com/trytooguangzhoutrading-ui/customer-development-skill
```

安装后重新打开 Codex 会话。若当前环境没有 skill-installer，可下载仓库 ZIP，解压后让 Codex 阅读 INSTALL.md 并执行 install.py；安装器会校验完整包，无需第三方 Python 库。详细步骤见 [INSTALL.md](INSTALL.md)。

需要能联网检索、读取网页并写本地文件的 Codex 环境，以及 Python 3.9+。工具能力与网站访问权由员工自己的环境提供。技能及本地脚本不调用独立 AI API，不要求单独申请 API Key；Codex 本身的使用条件与额度仍适用。

## 直接使用

在客户项目中输入：

```text
采集摩洛哥卡萨布兰卡经营智能眼镜的
批发商和进口商，优先有可归属公开业务入口的商户，完成后导出 Excel。
```

```text
在胡志明市采集智能手表和独立智能手表表带批发商，
与历史客户去重，补充新证据后导出表格。
```

安装后直接描述需求，无需每次输入技能名称。可让Codex为专用客户文件夹设置项目默认规则，之后说“继续采集”即可按已保存任务接续；多任务无法判定时只确认一次。无需手工填写技术字段。技能引导 Codex 自行安排检索与保存，员工主要接收结果和简短状态；Codex 自带工具卡和必要权限界面仍可能显示。

## 输出与工作方式

只交付 **一份Excel、一个“客户总表”工作表**。一个经营主体一行；国家、城市、市场、客户类型、资格状态为可筛选列，品牌店用客户类型区分；正式、渠道储备和待核用状态列区分。主体编号、目标产品、白牌标记、实际联系、来源网址、缺口和下一步留在同一行，当前市场及采集进度置于表头。没有客户的市场不创建空模板占用客户行。

研究遵循“统一主库与配置 → 国家和城市目录 → 当前城市渠道与联系生态 → 市场目录和顺序 → 当前市场铺具名商户池并持续补证 → 核验查重 → 统一客户总表”。所有市场共用主库，跨市场同主体不重复计净新增。

白牌“已核”指本任务至少一项白牌产品有证据；未取得足够白牌证据为“待核”。目前所读仅品牌商品的另记实际所见，没有看到不能写成不存在。白牌待核不阻塞其他条件满足的独立商户。品牌店身份须有证据，店名、Logo或只销售某品牌不能替代身份核验。电话与WhatsApp分别核，官网首页和地址不能代替实际联系，客服不自动当采购人。

每批固定当前市场。预算用尽、达到阶段数量、访问受阻或暂缓都保留该市场未完成，不能自动跳第二市场。市场完成须有真实目录／分区边界和逐一处理依据；无法证明全场覆盖时只报告实际覆盖，不把网上搜到的几家当完整市场。国家／城市／市场目录也注明已知范围和待预研部分，列出一城不等于全国已列全。

A重点客户另需实际经营能力和有效时间窗内带日期的经营活动；B为其余合格客户，级别不表示采购意愿或成交概率。资料缺失和读取失败留真实限制，不凑数量。

渠道可扩展到公开官网、地图、商业目录、平台商户、社交商业页面、展会/协会名录、公开采购需求和用户提供名单。海关及商业数据库需员工环境已有访问权，不会因为安装技能就获得付费数据。

新项目使用本地 JSON 主库、批次和备份；Excel 用于交付。已有客户 Excel 可保持为主库，由 Codex 使用可用表格工具增量更新。多人或换电脑时需要另行共享经授权的主库；安装技能不会自动同步企业客户。建议当前由一名专员负责同一主库写入。

可开发候选不表示采购意愿、采购权限或联系可达性已确认。技能负责获客资料研究与交接，不自动发送邮件、私信、询盘或电话，不处理报价、订单及销售跟进。无合格结果时据实导出，不凑数。

## 1.6.0 当前修复

- 恢复“先铺相关具名商户池、再持续补证”的执行方式；复用历史入口和回执，针对真实缺口补读，不把反复搜索或档案行数当客户产出。
- 项目检查直接返回已有Excel活动任务、原研究日志、配置差异和当前接续纠正；不新建客户库，旧任务的历史下一步不覆盖当前纠正。
- 同一实际查询／页面不能靠换entry_id、用途或分工标签重复领取；保留不同真实游标、查询提供方及有实际变化条件的重读。旧日志兼容读取，不补造历史。
- 有可读依据的相关渠道储备仍为candidate，在单一客户总表显示“渠道储备”，与“正式”“待核”区分；不升级正式资格、不计新增合格客户。无相关依据的纯元件／维修材料只留目录观察。
- 市场顺序、单表、白牌非门槛及品牌店分类继续保留。80次／45分钟是上限，有实读依据可提前交接范围复核；当前市场仍未完成，不自动换市场。

这次修复可用于当前任务的发现与接续，不重置已用预算，也不重写冻结事实。产品、地域或准入政策明确改变时才建立对应新任务。程序测试通过不表示实际客户产出已经改善。

## 历史版本与旧任务

1.4.0增加发现／补证／联系投入记录、路线暂缓和配置差异提示；1.3.1确定五类主营和音频附带；1.3增加唯一主库绑定、渠道预研、接续和纠错机制。这些版本的white_label_required任务曾要求同目标产品白牌证据，并排除官方店／专卖店；旧任务、原客户记录和冻结交付保留当时政策，不按当前默认静默重写。仅“继续”仍接续原任务；明确采用新政策时建新任务并对统一历史库查重。

功能验证与真实业务验收分开，见[验收方法](skills/customer-development/references/business-acceptance.md)。安装不会自动同步公司配置，也不会自动把旧客户升级为新政策合格。

## 维护与验证

```sh
python3 -m unittest discover -s skills/customer-development/scripts -p 'test_*.py' -v
python3 install.py --verify-only
```

修改发布文件后重新生成校验清单：

```sh
python3 tools/build_release.py
```

生成带顶层目录的安装 ZIP（输出需在仓库外）：

```sh
python3 tools/build_release.py --output ../customer-development-kit-1.6.0.zip
```

脚本测试验证数据完整性、证据引用约束、幂等、备份、并发和 XLSX 格式。它们不证明联网来源真实，也不保证每个国家都能采到相同数量。变更业务规则后，应在独立测试目录用代表性任务复核。

# 客户自动采集 · Codex Skill

员工在 Codex 输入国家、城市、客户类型或定向产品需求，自动完成公开资料研究、主体核验、联系归属、历史查重和 Excel 导出。

当前版本：**1.3.1**。先保存任务与断点，按公司配置确定画像和当地渠道，只将有目标白牌产品证据和实际联系入口的对象列为可开发客户。资格按任务保存，A/B优先级有实际证据与时效依据。

默认主营：**智能眼镜、智能手表、智能手表表带、智能手环、智能戒指**。**蓝牙耳机、蓝牙音响为附带拓展**，仅同渠道顺带保留，不占主营合格指标。员工每次明确指定一类或多类时，按专项需求执行。

## 员工安装

在 Codex 粘贴：

```text
使用 $skill-installer 从这个 GitHub 仓库安装 skills/customer-development：
https://github.com/trytooguangzhoutrading-ui/customer-development-skill
```

安装后重新打开 Codex 会话。若当前环境没有 skill-installer，可下载仓库 ZIP，解压后让 Codex 阅读 INSTALL.md 并执行 install.py；安装器会校验完整包，无需第三方 Python 库。详细步骤见 [INSTALL.md](INSTALL.md)。

需要能联网检索、读取网页并写本地文件的 Codex 环境，以及 Python 3.9+。工具能力与网站访问权由员工自己的环境提供。技能及本地脚本不调用独立 AI API，不要求单独申请 API Key；Codex 本身的使用条件与额度仍适用。

## 直接使用

在客户项目中输入：

```text
采集摩洛哥卡萨布兰卡经营智能眼镜的
批发商和进口商，优先有可归属公开业务入口的商户，完成后导出 Excel。
```

```text
在胡志明市采集智能手表和独立智能手表表带批发商，
与历史客户去重，补充新证据后导出表格。
```

安装后直接描述需求，无需每次输入技能名称。可让Codex为专用客户文件夹设置项目默认规则，之后说“继续采集”即可按已保存任务接续；多任务无法判定时只确认一次。无需手工填写技术字段。技能引导 Codex 自行安排检索与保存，员工主要接收结果和简短状态；Codex 自带工具卡和必要权限界面仍可能显示。

## 输出与工作方式

Excel 包含四张工作表：

| 工作表 | 内容 |
| --- | --- |
| 可开发客户 | 符合本轮研究条件、关键证据充分且有可归属业务入口的候选 |
| 待核线索 | 存在缺证、冲突、主体关系未定或仅属于主线外附带拓展的对象 |
| 来源证据 | 来源网址、读取时间、读取层级、支持内容和限制 |
| 采集说明 | 本轮范围、数量、已知限制和接续事项 |

研究遵循“项目主库与统一配置 → 任务断点 → 当地六类渠道地图与联系生态 → 相关大型到小型渠道逐店发现 → 查重 → 主体、精确地域、白牌产品与联系准入 → 预检保存 → Excel”。电话与 WhatsApp 分别核验，商户客服不自动当采购联系人，搜索摘要不自动升为已核事实。

品牌方、官方品牌店和品牌专卖店排除；混合经营的独立商家须有本轮目标产品的白牌经营证据。仅官网首页、地址或无法私信的展示主页不能代替联系方式。A重点客户还须有实际经营能力和有效时间窗内的经营活动证据；读取时间不能代替活动时间。B为其余符合准入的客户；等级不表示采购意愿或成交概率。

任务先建档，再保存市场/商圈、通信/社交、电商入口和语言资料；规模未知不猜大中小，预研不全明确记录限制，不把市场管理处当商户联系。

渠道可扩展到公开官网、地图、商业目录、平台商户、社交商业页面、展会/协会名录、公开采购需求和用户提供名单。海关及商业数据库需员工环境已有访问权，不会因为安装技能就获得付费数据。

新项目使用本地 JSON 主库、批次和备份；Excel 用于交付。已有客户 Excel 可保持为主库，由 Codex 使用可用表格工具增量更新。多人或换电脑时需要另行共享经授权的主库；安装技能不会自动同步企业客户。建议当前由一名专员负责同一主库写入。

可开发候选不表示采购意愿、采购权限或联系可达性已确认。技能负责获客资料研究与交接，不自动发送邮件、私信、询盘或电话，不处理报价、订单及销售跟进。无合格结果时据实导出，不凑数。

## 1.3.1 产品重点更新

- 默认主线改为五类主营，耳机和音响仅同渠道附带；明确音频专项仍支持。
- 独立智能手表表带单列，核独立销售、智能表适配与白牌证据；兼容品牌型号不等于品牌商家。

## 1.3 的可靠性改进

- 项目绑定唯一主库、有效规则和补充查重资料，新窗口沿用同一配置；已有Excel保留为权威主表，不自动重造空JSON库。
- 新采先完成六类渠道地图与实际联系生态，再按有据的大型→中型→小型渠道展开；路线、分页和实际商户采集可追溯。
- 补采已见的当地业务消息入口，核显示号码与链接目标，电话不自动推Zalo/WhatsApp。

- 修复地区覆盖错用、历史问题关闭丢失、重复关系处理受行顺序影响的问题。
- 关键身份、地域、产品、白牌或联系冲突阻止进入正式表；已排除对象重新纳入必须保留撤销依据，避免主库和表格结论相反。
- 支持有归属证据的WhatsApp号码、数字链接和商家短链，不从电话猜测账号。
- 当前范围客户表结合最新纠错及联系状态重新计算；历史批次保留当时交付结果。
- “继续”有活动任务索引、未读入口和未结问题；本轮新增合格客户与已有客户更新分别计数。
- 后台保存查询、页面、分页、实际尝试、渠道可用性和停止原因。默认按渠道覆盖推进，20个新增合格是阶段目标；每轮最多80次尝试或45分钟，员工要求可覆盖。路线未完只交付阶段结果并保存接续点，不把少量结果或达到20当成全城已完成。
- 除A/B依据外，展示可证的供货适配、目标产品覆盖、买家偏好与采购入口，按员工明确的业务优先项排序，不编造成交分数。

## 开源范围

仓库仅包含通用采集规则、地区模板、运行脚本、虚构格式示例和安装说明。**不包含现有客户名单、真实联系方式、私有采集记录、账号或密钥。**客户数据保存在员工自己的工作区，不上传此仓库。项目采用 [MIT License](LICENSE)。

这是在 Codex 会话中执行的 Skill，不是无人值守 SaaS。定时任务需另行由用户配置宿主自动化；联网来源的可用性会影响每批结果。

## 更新已有安装

下载新版完整仓库，按 [INSTALL.md](INSTALL.md) 使用 `install.py --replace`；安装器会备份旧技能。选择原安装所在目录，不重复安装到另一套路径。旧客户工作区和人工备注保留；安装器不覆盖公司配置。主管确认产品重点后，由Codex在原配置中更新主线和附带字段，保留其他设定；旧冻结批次不按新默认重写。旧批次可读取导出，新批次使用新版结构和门槛。未提交的1.0/1.1批次须在最新主库上新建快照并补齐新契约，不能只改版本号。新提交使用批次 schema 3；旧结果保持历史视图。

## 维护与验证

```sh
python3 -m unittest discover -s skills/customer-development/scripts -p 'test_*.py' -v
python3 install.py --verify-only
```

修改发布文件后重新生成校验清单：

```sh
python3 tools/build_release.py
```

生成带顶层目录的安装 ZIP（输出需在仓库外）：

```sh
python3 tools/build_release.py --output ../customer-development-kit-1.3.1.zip
```

脚本测试验证数据完整性、证据引用约束、幂等、备份、并发和 XLSX 格式。它们不证明联网来源真实，也不保证每个国家都能采到相同数量。变更业务规则后，应在独立测试目录用代表性任务复核。

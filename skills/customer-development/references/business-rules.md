# 客户采集判断规则

适用目标：员工输入需求后，由 Codex 自动研究、整理并导出客户表格。工作止于可追溯客户资料交接，不执行消息、邮件、询盘、电话、报价或销售跟进。供货条件缺失不阻塞公开研究，也不能用竞品资料填成我方能力。

## 1. 规则优先级与任务范围

先确定规则适用的地区、产品和任务，再按本次用户要求 → 同范围最新明确纠正 → 当前工作区有效配置 → 本技能默认模板处理。一次定向采集的临时要求不自动改成永久公司规则。规则冲突影响某个对象时，保留待核并继续其余对象，无需逐条中断员工。

固定产品为：智能眼镜、智能手表、智能手环、智能戒指、蓝牙耳机、蓝牙音响（音箱）。未指定产品时使用此范围；明确指定一类或几类时，仅统计本轮要求的产品。六类没有预设优先级。普通配件等相邻品类可保留研究线索，不能自动扩大产品范围或计入本轮产品匹配。

## 2. 分产品识别

| 产品 | 保存的具体依据 | 常见误判 |
| --- | --- | --- |
| 智能眼镜 | 商品型号及明确的音频、摄像、显示或其他电子功能，功能分别记 | 普通眼镜、镜框、滤光镜不能仅因名称含 smart 算智能眼镜；蓝牙音频不自动等于AI或摄像 |
| 智能手表 | 具体型号、商品正文及可辨认的智能功能 | 普通石英表、LED数字表、赠品、图片上未辨清的腕表不自动纳入 |
| 智能手环 | 具体手环型号及电子功能 | 表带、首饰手链、随表附件不能当智能手环 |
| 智能戒指 | 具体型号及电子功能；健康监测、NFC等功能分开记 | 普通戒指、智能戒指充电座或配件不算成品；不能从“智能”名称推健康测量能力 |
| 蓝牙耳机 | 具体耳机商品及蓝牙／无线连接证据 | 只写耳机大类、纯有线款、耳机保护套不足以证明蓝牙耳机 |
| 蓝牙音响 | 具体音响／音箱商品及蓝牙功能证据 | 有音响分类或只标有线／其他无线协议，不直接当蓝牙音响 |

一主体可对应多个产品，各自保留商品、功能、读取日期与状态。当前在售、售罄、预售、历史经营分开；售罄可以证明曾经营该产品，但不证明当前有货。没有型号不强造型号；足以识别的实际具体商品可以记录“型号未公开”。用户要求某项功能时，只有该功能有证据的产品才满足本轮要求。

## 3. 分类与交接门槛

| 结果 | 处理 |
| --- | --- |
| 可开发客户 | 主体可区分；符合指定地域或明确允许的渠道范围；产品／渠道证据满足本轮规则；至少一个可归属公开业务入口；必需条件无未解决冲突。它表示可交销售进一步开发，不表示采购意向已确认。 |
| 待核线索 | 对象有相关性，但缺主体桥接、具体产品、地域关联、业务入口或本轮必需的批发依据；或只读到搜索摘要、存在关键冲突。写具体缺口与下一步。 |
| 排除／历史 | 有证据表明不符合本轮目标、明确失效或属于已知重复对象。后台保留理由，继续参与去重，不计新增可开发客户。 |

部分地区可明确允许“可靠电子／配件渠道，但目标产品尚未证实”的渠道候选；仅在用户选择或工作区规则明确启用此例外时使用，并标明“渠道适配、目标产品待核”。见 [regional-profiles.md](regional-profiles.md)。不能把地区例外扩展为所有任务。索引摘要可用于发现与待核，不能单凭索引填入已核事实或升级为可开发客户。

采购负责人、采购方式、预算和采购意愿可以未知，不是默认交接硬门槛。公开资料已经支持时分别记录；不能从店面大小、粉丝、营业额估算、商品相似或老板姓名推定。没有税号不自动淘汰小商户。

## 4. 主体、地点与去重

- 区分平台、市场、品牌、经营公司、门店、柜台、联系人。目录网址不是商户官网，整页目录不是一个客户，商场管理处不是每家商户的业务入口。
- 一经营主体保留一份主记录，多平台店铺、分店、柜台和联系人关联保存。名称、域名、完整号码、平台商铺ID、地址及运营关系综合判断；相似名、共享平台域、同品牌或共用客服只产生关联提示。
- 关系未闭合时不强行合并，也不把关联不明的两条记录称为两个已核净新增法人；不移用另一方的商品、地址、号码或采购结论。
- 市场内、市场周边、同城其他区域、位置待核分开。城市级地址不能算具体市场覆盖；配送区域、注册办公地址、仓库、门店各自说明。
- 线上商家可依据可归属经营主体和当地经营关联判断，不要求必有实体零售店；只有配送范围不证明当地经营。
- 查重覆盖主库、历史待核、排除、旧别名及本批候选。已有主体发现新分店或新产品，记为补证／新增覆盖，不重复计新客户。跨国关联须有证据。

## 5. 联系信息

每项独立保存：原值、规范化值（能可靠规范化时）、所属商户、渠道身份、用途、岗位、来源、读取日期、可达状态。电话号码保留为文本，不补缺位、不猜国家码；原文与规范化值可并存。

- 电话 ≠ WhatsApp／Zalo／Telegram身份；必须有商户明示或可归属的实际链接。某号的WA证据不能移给同页另一号。
- 商户归属、渠道身份、可达性、联系人岗位、采购权限是不同判断。本技能不发消息或拨号，因此不能把“找到入口”写成“已试联可达”。
- 销售接单、客服、技术、售后、财务、采购分开。一般联系表单或向下游招经销商入口不是采购专用入口。
- 公司公共入口可以直接归公司，不强造姓名。平台客服、广告号码、网站开发者、招聘邮箱、市场代询、第三方物流入口不能作为商户直接联系。
- 网站社媒图标无实际href时不猜账号；外链可记录为商户给出的入口，原生页面不可读时如实标记，不声称账号内容已核。

## 6. 证据与事实边界

关键字段要能对应具体来源及支持片段，见 [sources.md](sources.md)。来源读到的事实、商户自述、模型推断与未核事项分别写。原URL完整缓存可以支持带历史限制的事实，不能冒充本轮实时读取；读取日期不是页面发布日期。HTTP 200、验证码或JavaScript壳不能证明正文已读。

“没有发现”“访问失败”“资料过时”“有反证”“主体冲突”分别处理。相同内容转载不算独立交叉证据；不机械要求每个字段两个网址。历史AI报告只能作为追查入口，不能作为当前独立证明。

公司综合批发自述和同主体具体目标产品可支持“公司级批发研究线索”，不等于该SKU已有批发条款。仅其他品类批发不自动升级目标产品批发。品牌先标记，不自动排除，也不把缺品牌资料当接受OEM／白牌。

SKU数量MOQ、混批金额、包装箱规、库存数、套装件数、运费门槛、定金、付款折扣分别保存。批发销售 ≠ 愿意从我方采购，进口记录 ≠ 现有采购需求。销量保留原平台口径、时间窗口、商品／变体范围，累计不改成月销量，估计不改成实测。

## 7. 自动执行与保存

不向员工展示逐条搜索、核验或复核步骤；遇到个别缺口自动转待核并继续。最终只交表格和必要的数量／限制摘要。不能以隐藏过程为由删除证据或谎称完成。

新增主体、旧客户补证、资料链接增量、纠错、来源读取和目录覆盖分别统计。数量不足如实交付，不降低门槛凑数。更新主库前重读版本，保留人工字段，单一写入者提交并回读；具体机制以入口及脚本契约为准。

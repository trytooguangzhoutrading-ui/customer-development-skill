# 客户采集判断规则

适用目标：员工输入需求后，由 Codex 自动研究、整理并导出客户表格。工作止于可追溯客户资料交接，不执行消息、邮件、询盘、电话、报价或销售跟进。供货条件缺失不阻塞公开研究，也不能用竞品资料填成我方能力。

## 1. 规则优先级与任务范围

先确定规则适用的地区、产品和任务，再按本次用户要求 → 同范围最新明确纠正 → 当前工作区有效配置 → 本技能默认模板处理。一次定向采集的临时要求不自动改成永久公司规则。规则冲突影响某个对象时，保留待核并继续其余对象，无需逐条中断员工。

支持七类产品，其中默认主营为智能眼镜、智能手表、智能手表表带、智能手环、智能戒指；蓝牙耳机、蓝牙音响（音箱）为附带。未指定产品时继承公司有效配置，新项目的products为五类主营，supplementary_products为两类音频。五类主营均需关注，不自行设置内部权重或配额。明确指定产品时仅按本轮专项执行，音频专项仍可作为正式目标。

附带音频只在同一渠道或同一商户的实际资料中顺带保存，注明具体产品、来源及“附带拓展／主线范围外”；仅有音频证据的对象进入待核线索，不计默认主营准入、合格数或阶段目标，不另开音频路线替代主营研究。兼营主营与音频的同一主体不重复计数；主营资格仍只看本轮products中的独立证据。其他普通配件不自动扩大范围。

先从公司配置生成本轮任务并保存基线，再建立[客户画像](customer-profile.md)和[当地渠道预研](local-ecosystem.md)；预研期间也保存断点。目标是经营本轮产品、具有转售业务的独立商户；官方品牌店和品牌专卖店同表分类采集；价格带、起订量、供货方式等我方资料缺失时记录未知，不虚构对方采购适配。大市场、连锁店、粉丝多不自动优先于实际匹配的小商户。

## 2. 分产品识别

| 产品 | 保存的具体依据 | 常见误判 |
| --- | --- | --- |
| 智能眼镜 | 商品型号及明确的音频、摄像、显示或其他电子功能，功能分别记 | 普通眼镜、镜框、滤光镜不能仅因名称含 smart 算智能眼镜；蓝牙音频不自动等于AI或摄像 |
| 智能手表 | 具体型号、商品正文及可辨认的智能功能 | 普通石英表、LED数字表、赠品、图片上未辨清的腕表不自动纳入 |
| 智能手表表带 | 可独立购买的表带商品，以及适配智能手表型号／接口的明确资料 | 随表附赠件不证明独立表带经营；普通传统表带、仅宽度相近不自动证明智能表适配；表带不当作完整手表或智能手环 |
| 智能手环 | 具体手环型号及电子功能 | 表带、首饰手链、随表附件不能当智能手环 |
| 智能戒指 | 具体型号及电子功能；健康监测、NFC等功能分开记 | 普通戒指、智能戒指充电座或配件不算成品；不能从“智能”名称推健康测量能力 |
| 蓝牙耳机 | 具体耳机商品及蓝牙／无线连接证据 | 只写耳机大类、纯有线款、耳机保护套不足以证明蓝牙耳机 |
| 蓝牙音响 | 具体音响／音箱商品及蓝牙功能证据 | 有音响分类或只标有线／其他无线协议，不直接当蓝牙音响 |

一主体可对应多个产品，各自保留商品、功能、读取日期与状态。当前在售、售罄、预售、历史经营分开；售罄可以证明曾经营该产品，但不证明当前有货。没有型号不强造型号；足以识别的实际具体商品可以记录“型号未公开”。用户要求某项功能时，只有该功能有证据的产品才满足本轮要求。

表内型号是可保存的信息，不是必须字段。商品卡、可归属的商户销售帖／目录、清晰销售图片／视频及可靠第三方原文均可证明实际经营，不要求自有官网或独立SKU详情页。资料须能识别目标产品并归属商户；空分类、泛广告和模糊腕表图仍不足，不能因表带兼容品牌把商户判成品牌专卖店。

## 3. 品牌与白牌判断

- 默认政策下，独立商户经营本轮主营产品并通过其他准入即可采集，销售品牌商品不构成排除理由。纯品牌方仍排除；可明确识别的官方品牌店、品牌专卖店按店铺主体采集并在统一总表标记“品牌店”类型。品牌公司与具体销售店铺分开，不能把纯品牌方改名成品牌店绕过排除。
- 店名、Logo、平台认证或检索词不能单独证明品牌关系。品牌店须有可读的官方／专卖身份依据；身份不明、经营主体冲突的留待核。
- 白牌只作“已核／待核”标记，不作默认准入。“已核”指本任务至少一项目标产品白牌已证实，写清商品及来源；尚无足够白牌证据标“待核”。目前所读商品只见品牌商品的，另写该事实，不等于该店没有白牌；未读、无法确认或资料矛盾均保留待核和缺口。
- 白牌判断仍需具体商品和来源。无品牌栏、无Logo、低价、外形相似或通用型号不证明白牌。明确无品牌／通用款属性须核商品、卖家归属及描述是否一致。
- 表带“兼容Apple Watch／Huawei”等只说明适配对象，不证明原厂商品、官方店／专卖店或白牌。独立销售、智能表适配、卖家身份与白牌标记分别留证。
- 白牌经营、OEM／定制能力、接受我方供货分别核实，不能互推。单纯白牌缺证／冲突不阻止默认政策下的主营准入；若也影响主体、产品或其他必需事实，仍按相关缺口待核。
- 用户明确不采某主体时按用户决定排除，保留原指令和范围，不伪造品牌方、停业等事实。
- 旧任务采用white_label_required时，继续按其原政策要求同目标产品白牌证据、排除官方店／专卖店。仅继续旧任务不自动换规则；明确采用新政策则新建任务，旧交付不改写。

## 4. 分类与交接门槛

| 结果 | 处理 |
| --- | --- |
| 可开发客户 | 已核独立经营主体和本轮买家角色，符合指定地域，至少一项本轮目标产品有可读经营证据，至少一个可归属实际联系入口，必需事实无未解决冲突且已查重。白牌已核／待核均可保留。 |
| 品牌店 | 已核官方品牌店或品牌专卖店身份，同时满足主体、目标地域、买家角色、产品、实际联系和去重要求；同表按客户类型区分，不计入独立商户数量，不表示已确认其采购权。 |
| 待核线索 | 缺主体桥接、具体产品、地域、实际联系或本轮必需角色证据；仅有搜索摘要；有影响必需条件的冲突。写具体缺口。仅白牌待核不属于把合格商户转待核的理由。 |
| 本任务排除 | 有证据证明地域、产品、买家类型或必需条件不符，或用户明确排除。只改变对应任务资格，不删其他任务资格。 |
| 实体排除／合并 | 有据确认纯品牌方、停业等事实，或与另一稳定ID为同主体。保留依据和历史，不重复计新增。官方店／专卖店在新默认下不作实体排除。 |

有实际相关成品3C／手机配件转售渠道依据、尚未证实目标产品的对象，可作渠道储备，同表保留“目标产品待核”，不计正式客户。纯元件、维修材料等且无相关渠道桥梁的仅保存目录观察，不凭“电子”标签充客户数；相关性未核但有具体追查入口的保留待核线索。分层细则见[merchant-discovery.md](merchant-discovery.md)。不能用相邻品类、目录类别或搜索摘要替代目标产品。资格只列有产品证据的品类，不因一种合格就把其他产品全部标已匹配。

主体事实、联系状态和各任务资格分别保存；一个商户可在眼镜任务合格、耳机任务不符。采购负责人、方式、预算和意愿可以未知，不是默认硬门槛；公开资料支持时另记，不能从店面、粉丝或老板姓名推定。没有税号不自动淘汰小商户。

## 5. 主体、地点与去重

- 区分平台、市场、品牌、经营公司、门店、柜台、联系人。目录网址不是商户官网，整页目录不是一个客户，商场管理处不是每家商户的业务入口。
- 一经营主体保留一份主记录，多平台店铺、分店、柜台和联系人关联保存。自有域名须有归属依据；电商／目录／社媒按平台加卖家ID或实际店铺URL识别，不能把同一平台域名当同一商户。未知网站关系采用更细的URL线索，不猜为独立站。
- 同名、相似名是弱提示，不能单独阻断另一个证据齐全商户。完整业务号码、自有域名等强关联需要核关系，共用客服仍不自动等于同主体。确认同主体后保存规范客户ID及合并依据，旧别名继续用于检索，不再要求规范主体与其已确认别名证明“彼此独立”。
- 关系未闭合时不强行合并，也不把关联不明的两条记录称为两个已核净新增法人；不移用另一方的商品、地址、号码或采购结论。
- 将用户的国家、城市、市场或地址要求落实为本任务明确地域范围；商户需匹配相应层级，或有来源支持的地名别称映射。同国跨城不能通过城市限定；同城不等于指定市场内。未知位置待核，有证据的越界对象只在本任务排除。
- 市场内、市场周边、同城其他区域、位置待核分开。指定“周边”但未定义边界时，保留原需求并采用有依据的具体边界；不能靠文字包含或猜测距离纳入。配送区域、注册办公地址、仓库、门店各自说明；城市级地址不能算具体市场覆盖。
- 线上商家可依据可归属经营主体和当地经营关联判断，不要求必有实体零售店；只有配送范围不证明当地经营。
- 查重覆盖主库、历史待核、排除、旧别名及本批候选。已有主体发现新分店或新产品，记为补证／新增覆盖，不重复计新客户。跨国关联须有证据。

## 6. 联系信息

每项独立保存稳定联系ID、原值及原文变体、可靠规范化值、所属商户、渠道身份、用途、岗位、来源、最后实际核验日期和状态。去空格／标点不应把同一个号码变成新入口；国际码不明确时不猜国家码，也不把本地号码强行与另一国家同号合并。电话与WhatsApp各自保留渠道身份和证明。

同一入口的失效更新应落到原联系ID，保留旧证据与历史，不能因格式不同留下一个“有效旧号”。未在本轮重新读取的入口标“历史沿用未复核”，不能因复制到新批次就刷新核验日期。若唯一合格入口被判失效，相关当前资格需转待核，等待其他有效入口；旧批次保留原时点记录。

- 正式交接至少一个实际入口：公开完整电话、业务邮箱、明确平台身份的WhatsApp／Zalo等业务联系、商户表单、实际私信或店铺聊天入口。只需满足其中一种，不要求全部齐备。
- 单纯官网首页、地址、地图点、不能确认私信入口的社交展示主页不能单独满足门槛；可作为主体或发现证据。官网发现联系页后，记录实际号码、邮箱、表单或消息入口，不只记录域名。
- 电话 ≠ WhatsApp／Zalo／Telegram身份；必须有商户明示或可归属的实际链接。某号的WA证据不能移给同页另一号。
- 商户归属、渠道身份、可达性、联系人岗位、采购权限是不同判断。本技能不发消息或拨号，因此不能把“找到入口”写成“已试联可达”。
- 销售接单、客服、技术、售后、财务、采购分开。一般联系表单或向下游招经销商入口不是采购专用入口。
- 公司公共入口可以直接归公司，不强造姓名。平台客服、广告号码、网站开发者、招聘邮箱、市场代询、第三方物流入口不能作为商户直接联系。
- 网站社媒图标无实际href时不猜账号；外链可记录为商户给出的入口，原生页面不可读时如实标记，不声称账号内容已核。

普通主页不能因“这个平台通常有私信功能”而改记为可联系。可读页面实际显示的消息按钮、表单或明确直达商户的联系链接可作入口证据；需要登录才能实际联系时记录限制。历史、失效或已知不可用入口不能单独使客户合格。采集不发送测试消息、不拨号，始终分清“入口存在”和“联系可达”。

## 7. 证据与事实边界

关键字段要能对应具体来源及支持片段，见 [sources.md](sources.md)。来源读到的事实、商户自述、模型推断与未核事项分别写。原URL完整缓存可以支持带历史限制的事实，不能冒充本轮实时读取；读取日期不是页面发布日期。HTTP 200、验证码或JavaScript壳不能证明正文已读。

“没有发现”“访问失败”“资料过时”“有反证”“主体冲突”分别处理。相同内容转载不算独立交叉证据；不机械要求每个字段两个网址。历史AI报告只能作为追查入口，不能作为当前独立证明。

公司综合批发自述和同主体具体目标产品可支持“公司级批发研究线索”，不等于该SKU已有批发条款。仅其他品类批发不自动升级目标产品批发，也不能替代目标商品证据。

SKU数量MOQ、混批金额、包装箱规、库存数、套装件数、运费门槛、定金、付款折扣分别保存。批发销售 ≠ 愿意从我方采购，进口记录 ≠ 现有采购需求。销量保留原平台口径、时间窗口、商品／变体范围，累计不改成月销量，估计不改成实测。

## 8. 开发优先级

先判断准入，再给合格客户排序。价值优先级与证据完整性分开，不用高分抵消身份、目标产品、地域或联系缺口，不输出成交概率或推算采购额。

| 等级 | 条件 |
| --- | --- |
| A：重点开发 | 已满足全部准入；另有实际批发、进口、分销或其他经营能力依据，以及活动发生日期在本任务新鲜度窗口内的可读持续经营证据。保留能力、活动日期、判断日期和来源；默认窗口180天，可按任务配置1–730天。 |
| B：正常开发 | 已满足全部准入，但经营能力、持续经营状态等不足以支持A。未知写未知，不因规模较小、缺税号或粉丝少直接排除。 |

先导出A，再B；同级用可解释、稳定的次序。待核和排除不赋A/B，单独记录补证优先事项。商家自述与独立证据仍需标明，不以一条“实力雄厚”宣传替代能力依据。最近经营动态的内容日期与本次读取日期分开，旧商品、历史进口或网站可打开不自动证明持续经营。日期未知、超窗或未来日期不能用于自动评A；这不等于商户已停业，也不淘汰其他准入通过的B类客户。活动窗口是排序依据，不是统一客户存活期限。

## 9. 自动执行与保存

不向员工展示逐条搜索、核验或复核步骤；遇到个别缺口自动转待核并继续。交付一个Excel中的统一客户总表及表头进度和必要的数量／限制摘要。不能以隐藏过程为由删除证据或谎称完成。

新主体、旧主体更新、同范围重新合格、首次进入新任务资格、联系与证据增量分别统计；本轮可开发条数不等于净新增客户数。按本任务产品×实际计划渠道记录未搜索、受阻、已搜索无合格结果和有研究结果，防止附带耳机／音响掩盖五类主营未搜；附带线索不计主线覆盖完成或合格阶段目标，不给各产品强行平均配额。数量不足如实交付，不降低门槛凑数。更新主库前重读版本，保留人工字段，单一写入者提交并回读；具体机制以入口及脚本契约为准。

待核问题使用稳定问题ID，记录对象、缺口、状态、尝试次数、下次触发条件；有新证据后显式关闭，导出仅展示未解决事项。访问受阻与无适配证据分开，不靠重复尝试累计虚假进展。

旧批次保留原时点记录，不用新规则静默改写历史或自动重评。旧客户进入新批次时按现行门槛补证；新任务关键证据不足者如实转待核，保留其他任务资格、原资料及人工字段。员工Excel纠错通过稳定ID和白名单字段回流：备注可更新，联系失效与资格疑点进入受控纠正／补核；不能把手工填“优质”直接变成A或绕过证据准入。

# 自动采集执行流程

员工只提供业务需求；本文件供 Codex 内部执行。默认不展示中间查询、任务拆分、候选判断或逐项审批。使用宿主要求的简短进度提示，最后交付Excel与简短结果。必须用户才能解决的关键范围缺失或真实工具故障，才集中说明。

## 1. 建立本批任务

读取当前工作区有效规则、历史主库、人工修正和接续状态，解析：地区／地址范围、产品、买家类型、特殊条件、任务模式、数量或时间要求。模式包括新采、继续、定向产品、指定名单补证。无产品限制时用固定六类；“全球”是有效范围，由实际来源分国家、语言与渠道分批，不强迫员工先选单国。

已有信息直接沿用。只有地区／全球范围无法判断、或关键条件冲突无法执行时才问一次；报价、采购人或型号供货条件未知不阻塞采集。把本轮要求和规则版本写入批次，数量目标是研究目标而非保证合格条数。

先确认本机实际可用的搜索、网页读取、浏览器、连接器与文件工具。使用Codex本身已有能力，不要求另建AI API密钥。某专有数据源不可用时继续其他来源，不把“已连接”写成“本轮已成功读取”。没有任何联网读取能力时只能处理已有资料，导出中说明本轮未完成实时采集。

## 2. 发现入口

两条线并行或顺序配合：

- 地域／渠道线：国家 → 城市 → 市场／商圈／企业目录 → 具体商户。
- 产品线：目标产品词／实际型号 → 商品原页／商户帖子 → 实际卖家与经营主体。

进口商、当地品牌和纯线上商家可直接由企业／贸易／店铺来源发现，不强行挂靠实体市场。来源适用边界见 [sources.md](sources.md)。

检索组合使用本地语言、常见拉丁转写／无声调写法及英文，围绕产品、买家角色、地名和证据缺口调整。例如：

| 用途 | 搜索骨架 |
| --- | --- |
| 新主体 | 当地产品词 + 批发／进口／分销角色词 + 城市 |
| 逐店 | 已确认市场名 + 产品词／商户目录／商户原名 |
| 商品核验 | 商户原名或自有域名 + 产品／型号 |
| 主体桥接 | 商户原名 + 自有域名／完整已见业务号／公开运营名称 |
| 联系入口 | 商户自站 + contact／about／供应商申请等当地词 |

页面中的“B2B”“supplier”“合作”可能是销售或招经销商，必须读上下文。不要把查询用词当事实。名称翻译和地址改写保留原文，不能凭近似音译合并商户。

## 3. 先初筛和查重，再集中补证

发现候选立即记录真实入口，并对照主库、待核、排除及本批别名查重。明确地域／产品不符的留排除原因；属于旧主体的做增量补证。相似名、共号等只记潜在关联，由可用证据继续判断。

对相关对象读取最有可能改变结论的页面：实际商品、商户身份、经营地址、业务联系与当前任务要求的批发依据。不要为了补齐所有社媒或追求来源数量无限扩查。

每对象围绕四个基础问题：主体是谁、与目标地域有何关系、目标商品／允许的渠道依据是什么、至少一个公开业务入口属于谁。按 [business-rules.md](business-rules.md) 自动分类。采购权限未知可留给销售核实，不能把它伪装为已确认，也不默认阻塞其他条件已满足的交接。

## 4. 有限补查与失败处理

一个入口失败后，可使用已发现的同商户其他正常公开入口、可读原URL缓存或独立目录。缓存带历史标签；搜索摘要留待核。不绕过登录、验证码、权限墙、遮挡图片或受保护字段，不猜商品／分页／社交URL。

相同页面在没有新条件时不反复重试。一个来源失败不拖停整批；保存失败类型和真实替代路径。能改变结论的缺口优先，新增无关外链不作为决定性进展。

研究可按地域或来源分给子任务；每个子任务产出证据和建议变更，不直接同时写主库。单人也可能开多个任务，因此保留单写入者和写前版本检查。

## 5. 覆盖账本与结束条件

后台记录实际搜过的查询、已读URL、实际看到的目录卡与分页、已研究商户、重复／排除、失败入口、尚未读的真实链接。目录宣称总数、实际看到卡数、已读详情数、可开发客户数分开。

以下任一出现时可以结束本批并交付已有结果：达到本次明确的时间／研究范围；本批已发现的主要可执行路径处理完；当前工具限制使剩余路径不可执行；剩余问题只能由商户回答。保存结束原因和未完成队列，不把批次结束写成整个国家或市场采尽。

连续低产时检查是否一直重复旧源，切换实际可用渠道并复核未读队列。历史地区曾使用“三轮有效研究无进展”触发复核；这不是本技能全局停止阈值。采用任何固定阈值都以当前任务／地区配置为准，失败请求和重复查询不能伪装有效研究轮次。

## 6. 写入和导出

按稳定ID准备增量，把来源与对应事实关联；有疑点的记录进入待核，员工不需要逐条批准。保存前重新核主库版本，解决可确定的字段合并；冲突无法安全解决的保留待合并成果，不覆盖人工记录。

自动校验和回读完成后，导出本批可开发客户、待核线索及来源证据。排除与完整执行轨迹留后台；按任务需要在采集说明记录范围、实际数量和限制。手机号、店铺ID、邮编按文本保存，保持原文和完整URL。脚本的结构校验不等于事实已核，来源阅读仍由Codex完成。

最终回复通常只包含一个Excel文件链接、一句可开发／待核数量和必要限制。不要给员工再分配搜索、去重、逐条审核等中间工作。定时任务只有用户明确要求时才另行配置；安装技能、写入队列或“继续采集”都不代表已启动后台调度。

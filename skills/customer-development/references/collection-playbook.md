# 自动采集执行流程

员工只提供业务需求；本文件供 Codex 内部执行。默认不展示中间查询、任务拆分、候选判断或逐项审批。使用宿主要求的简短进度提示，最后交付Excel与简短结果。必须用户才能解决的关键范围缺失或真实工具故障，才集中说明。

默认流程：读取公司配置与明确需求 → 创建任务和基线 → 最小地区预研 → 线下／线上发现并保存断点 → 主体去重与本任务资格核验 → 问题闭环及A/B优先级 → 逐条预校验 → 提交有效结果 → 导出Excel。预研在后台完成，不让员工手工搜集市场和平台清单。

## 1. 建立本批任务

读取当前工作区有效规则、公司配置、历史主库、人工修正和接续状态，解析：地区／地址范围、产品、买家类型、特殊条件、任务模式、数量或时间要求。模式包括新采、继续、定向产品、指定名单补证。未指定产品时继承有效公司配置，公司未缩小范围时用固定六类；“全球”是有效范围，由实际来源分国家、语言与渠道分批，不强迫员工先选单国。

已有信息直接沿用。只有地区／全球范围无法判断、或关键条件冲突无法执行时才问一次；报价、采购人或型号供货条件未知不阻塞采集。把本轮要求、明确地域范围和规则版本写入批次，并在访问任何新来源前保存主库基线。数量目标是研究目标而非保证合格条数。

新采建立新批次；接续读取明确批次的任务、已保存证据、问题和未读入口，不另建空任务假装已接续。预研、候选和失败结果都增量保存断点，尚不满足提交契约的草稿也保留。主库变更后先重新核对再提交，不能为绕过版本冲突只改哈希。步骤与命令见 [persistence.md](persistence.md)。

先确认本机实际可用的搜索、网页读取、浏览器、连接器与文件工具。使用Codex本身已有能力，不要求另建AI API密钥。某专有数据源不可用时继续其他来源，不把“已连接”写成“本轮已成功读取”。没有任何联网读取能力时只能处理已有资料，导出中说明本轮未完成实时采集。

## 2. 明确画像并预研当地渠道

按 [customer-profile.md](customer-profile.md) 记录目标转售商家类型、目标产品、白牌条件、排除项及已知我方供货条件。品牌方、官方店和品牌专卖店排除；独立混合经营商家需要本轮目标产品的白牌经营证据。供货价格、MOQ、定制能力不明时保留未知，不阻塞其他公开研究。

按 [local-ecosystem.md](local-ecosystem.md) 建立或复核本轮地区配置：

- 实际适用语言、地名别称、产品／买家角色词。
- 电子数码批发市场、综合市场相关区域、批发商场、商超百货、独立批发商及其真实目录／地图入口。
- 当地商户实际使用的电话、邮箱、消息平台和商业社交入口；实际可访问的电商平台及卖家识别方法。
- 各路线的相关性、读取可行性、证据来源、限制与下一步。

市场按类型和有依据的规模记录，没有可靠规模资料就标未知；不按“大→中→小”机械推进。优先产品商户集中、白牌适配且有可读取入口的路线。普通商超、市场管理处和购物中心本身不自动成为采购客户。

已有预研在范围仍适用且资料未出现变化时复用，保留实际检查日期；读取本地旧记录不算重新访问来源。换国家、城市、产品或来源失效时更新。先取得支持本轮研究的最小可用路线即可开始找商户，其他路线继续补齐；无需等全城市场地图完整。全球任务分地区完成预研，不虚构一套全球通用平台。个别市场／平台不可读就标限制并启用其他有效路线，不假称全量覆盖。

## 3. 线下与线上发现入口

两条线并行或顺序配合：

- 地域／渠道线：国家 → 城市 → 市场／商圈／企业目录 → 具体商户。
- 产品线：目标产品词／实际型号 → 商品原页／商户帖子 → 实际卖家与经营主体。

独立进口商、分销商和纯线上商家可直接由企业／贸易／店铺来源发现，不强行挂靠实体市场，也不等全部实体市场查完才开始线上研究。电商路线按“目标白牌商品 → 实际卖家 → 经营主体 → 地域与实际联系”推进，不能把平台商品当成某个卖家的商品。来源路线及边界见 [sources.md](sources.md)。

检索组合使用本地语言、常见拉丁转写／无声调写法及英文，围绕产品、买家角色、地名和证据缺口调整。例如：

| 用途 | 搜索骨架 |
| --- | --- |
| 新主体 | 当地产品词 + 批发／进口／分销角色词 + 城市 |
| 逐店 | 已确认市场名 + 产品词／商户目录／商户原名 |
| 商品核验 | 商户原名或自有域名 + 产品／型号 |
| 主体桥接 | 商户原名 + 自有域名／完整已见业务号／公开运营名称 |
| 联系入口 | 商户自站 + contact／about／供应商申请等当地词 |

页面中的“B2B”“supplier”“合作”可能是销售或招经销商，必须读上下文。不要把查询用词当事实。名称翻译和地址改写保留原文，不能凭近似音译合并商户。

## 4. 初筛、查重、核验与价值排序

发现候选立即记录真实入口、发现渠道及对应产品，并对照主库、待核、排除及本批别名查重。事实性排除须有依据；查不到产品或品牌关系时保留待核，不能等同“不经营”或“品牌方”。明确地域／产品不符只影响本任务资格；属于旧主体的做增量补证。

平台店铺按实际店铺ID或URL识别，同平台域名不同卖家不是重复；相同名称只产生弱提示，不单独拦截证据齐全的商户。确认同主体后维护规范客户ID与别名关系，再沿规范主体更新；保留确认依据，不能反复把已合并别名当成待证明独立的商户。

对相关对象读取最有可能改变结论的页面：实际目标商品及白牌属性、商户及品牌关系、经营地址、实际联系入口与当前任务要求的经营角色依据。不要为了补齐所有社媒或追求来源数量无限扩查。

逐项判断主体与转售角色、明确地域范围、目标产品、同产品白牌关系、实际联系、供货适配及必需条件，按 [business-rules.md](business-rules.md) 自动分流。城市限定不能仅凭同国地址通过，市场限定不能用同城位置代替。供货未知不编造适配，已知冲突不能作为正式结果；员工明确的必需条件逐项核实。仅官网首页、地址或无已见消息入口的社交主页不能满足联系门槛。采购权限未知可留给销售核实，不能伪装已确认，也不默认阻塞其他条件已满足的交接。

全部准入通过后才评A/B。优先深查已有批发／进口／分销／经营能力及实际近期经营活动依据的对象，采用任务保存的活动日期窗口；今天读到旧活动不能变成A。合格小商户仍可保留。缺关键证据的对象单列待核，补证优先看能否解决资格缺口，不用粉丝量、店面大小或虚构分数代替。

## 5. 有限补查与失败处理

一个入口失败后，可使用已发现的同商户其他正常公开入口、可读原URL缓存或独立目录。缓存带历史标签；搜索摘要留待核。不绕过登录、验证码、权限墙、遮挡图片或受保护字段，不猜商品／分页／社交URL。

相同页面在没有新条件时不反复重试。一个来源失败不拖停整批；保存失败类型和真实替代路径。将待核项记为稳定问题，含相关客户、缺口、状态、尝试次数、下一行动和触发条件。补证完成后用新依据显式关闭；访问仍受限则记受阻及可重试条件。不要通过清空文本丢掉历史，也不要把已解决问题永远留在待核表。能改变结论的缺口优先，新增无关外链不作为决定性进展。

研究可按地域或来源分给子任务；每个子任务产出证据和建议变更，不直接同时写主库。单人也可能开多个任务，因此保留单写入者和写前版本检查。

## 6. 覆盖账本与结束条件

后台记录实际搜过的查询、已读URL、实际看到的目录卡与分页、已研究商户、重复／排除、失败入口、尚未读的真实链接。目录宣称总数、实际看到卡数、已读详情数、可开发客户数分开。

按本轮产品×计划渠道保留覆盖格，每个产品至少能看出是否真正研究过。未搜索、访问受阻、已搜无合格结果、有研究结果分别记录，配实际尝试、来源和限制；发现渠道归因到具体商户。同一主体可由多条路线补证，但净新增只算一次。不用一批耳机客户代表眼镜／戒指也已覆盖，不强制六类平均分配客户配额。

按来源路线分别记录新主体、旧主体更新、重新合格、首次任务资格、合格A/B、待核、品牌排除、重复和联系缺口；比较实际有效产出以调整下一轮顺序。渠道转换率只用本轮有清楚分母的实际研究记录计算，不以搜索结果估计数当已采集商户数，也不当成交率。资料缺少分母时只报告原始数量。

以下任一出现时可以结束本批并交付已有结果：达到本次明确的时间／研究范围；本批已发现的主要可执行路径处理完；当前工具限制使剩余路径不可执行；剩余问题只能由商户回答。保存结束原因和未完成队列，不把批次结束写成整个国家或市场采尽。

连续低产时检查是否一直重复旧源，切换实际可用渠道并复核未读队列。历史地区曾使用“三轮有效研究无进展”触发复核；这不是本技能全局停止阈值。采用任何固定阈值都以当前任务／地区配置为准，失败请求和重复查询不能伪装有效研究轮次。

## 7. 写入和导出

按稳定ID准备增量，把来源与对应事实关联；业务证据不足的记录进入待核，结构错误则进入修复队列，二者分开。先逐条预校验：坏记录及原始输入完整留存，合格子集明确生成待提交包，并在本轮限制中记被隔离数量和原因；不得静默删掉错误记录后宣称全部成功。任务或共享来源错误需修复后才能提交依赖它们的记录。员工不需要逐条批准。

保存前重新核主库版本，解决可确定的字段合并；冲突无法安全解决的保留待合并成果，不覆盖人工记录。有效包仍以单次原子写入提交，保存备份并回读。若导出失败，直接从已提交批次重试导出，不重新采集或重复计新增。

自动校验和回读完成后，导出本批可开发客户、待核线索及来源证据。合格表A在前、B在后，保留实际合格产品、商家类型、品牌经营类型、白牌证据、市场／位置精度、实际联系及最后核验状态、经营动态、优先级及理由、未解决缺口。排除与完整执行轨迹留后台；采集说明记录画像、渠道预研和产品覆盖摘要、本轮条数与净新增等不同数量、被隔离记录及限制。手机号、店铺ID、邮编按文本保存，保持原文和完整URL。脚本的结构校验不等于事实已核，来源阅读仍由Codex完成。

员工反馈表格错误时，使用带稳定客户／联系ID的纠错模板及受控导入；只处理允许的采集纠错字段。备注、入口失效、需复核事项分别回流，先核模板基线和差异再自动应用已授权纠错，保留备份与记录。分类疑点触发补核，不能无证据直接晋级A／正式客户；销售过程不在此模板处理。旧输出留原样，新结论通过新批次或纠错记录体现。

最终回复通常只包含一个Excel文件链接、一句可开发／待核数量和必要限制。不要给员工再分配搜索、去重、逐条审核等中间工作。定时任务只有用户明确要求时才另行配置；安装技能、写入队列或“继续采集”都不代表已启动后台调度。

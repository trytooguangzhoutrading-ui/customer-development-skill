# 先铺商户池，再持续补证

沿用项目主库和历史记录，先找到相关商户，再把证据补到可以交接。发现、资格和跟进状态是不同维度；不把“待核”解释成不采，也不把历史储备条数解释成正式客户数。

## 1. 接续

从项目绑定和inspect定位当前规则、公司画像、唯一主库及活动任务，读取实际表头、稳定ID、人工栏和全部补充查重源。用户指定历史方法时实读原表及典型批次，复用可证做法，不机械复制旧产品范围、品牌排除或市场推进策略。仅继续旧任务保留原政策；本次明确纠正另建任务，沿用历史资料和断点。

保存任务范围和来源基线后开展研究。JSON用workflow；已有Excel继续原主表，不为使用CLI另建JSON库。具体保存契约在[project-context.md](project-context.md)和[research-progress.md](research-progress.md)。

## 2. 建目录与选择真实入口

按国家、城市、市场建有来源的目录，按[local-ecosystem.md](local-ecosystem.md)完成当前城市六类渠道及联系生态初查。现有同范围预研可沿用并保留日期；真实访问受阻不当作没客户。

市场排序分别保存产品／转售渠道适配和总体规模证据。目录只是已知范围，不把一城、几个市场或电子摊位数推成全国完整覆盖或穿戴密度。当前市场按楼栋、分区、街段、分页或真实商户卡展开；所有已见入口记已读与下一位置。

同时使用两条发现方向：目录／市场资料到具体商户；目标商品／商业广告到实际卖家、作者主页或业务账号。先提取同一入口中所有相关具名商户，再补各自决定性事实。搜索只用来定位入口，不以换词反复返回同一排名文代替逐店展开。方法见[merchant-discovery.md](merchant-discovery.md)。

## 3. 先保存，再分类

发现阶段保存商户原名、真实来源、已见商品或渠道线索、位置线索及历史关联；未知照实标明，不为保存相关线索要求官网、白牌、税号、完整型号或采购人。只有无归属名字、纯元件／维修材料且无相关性依据的，留目录观察供追查，不计客户。

| 本轮层次 | 判断与下一步 |
| --- | --- |
| 正式客户 | 至少一项本轮目标产品经营，主体、地域、买家角色、实际联系及去重通过；按事实记录具体市场关系。 |
| 渠道储备 | 可读资料已证相关成品3C／手机配件转售渠道，主营产品尚缺证；继续查该商户商品或商业帖。 |
| 待核线索 | 有目标产品或相关渠道线索，但主体、位置、联系、来源或必需角色仍不足；标决定性缺口。 |
| 目录观察 | 没有目标或相关成品渠道依据；留研究日志、原来源与恢复条件，不混入客户统计。 |

正式资格见[business-rules.md](business-rules.md)。品牌店同表标类型，白牌待核不挡其他事实已齐的独立商户。城市正式与场内正式分开：城市客户没有柜号可以保留，不能冒称已采到当前市场商户。

## 4. 持续补证与主体合并

先补能改变分类的事实：相关商户的实际目标商品、商品卖家的主体桥接、地域或柜位归属、可归属业务联系。跟随已见作者、店铺、关于我们及联系链接；不要只停留在广告页或商场管理处。一个对象暂时补不齐时继续同市场其他入口，不让少数旧客户吞掉整轮。

电话、邮箱、平台聊天等任一可归属实际入口可满足联系下限，其他已见入口继续补；电话不推Zalo／WhatsApp，客服不当采购，找到入口不当试联。无法取得的公开资料留缺口，非必需的白牌、OEM、MOQ或采购意愿不无限深挖。

按主体、完整业务联系、独立域名、平台卖家ID和可读法律／经营关系查重。换名、分店、新产品和补联系方式都更新原稳定ID。域名或电话号码相同只作关系线索，确认后合并，不把平台共域误并全部店铺。旧候选晋级、旧资料复核和新主体分别计数。

每个分区／入口后检查发现与补证增量，并行工作共享派发和已读清单。同URL新分页或真实恢复条件可重读，改变动作标签、工作分工或入口编号不产生新覆盖。失败无变化不循环，原文只读部分就记录部分。

## 5. 当前市场推进

当前市场未读、受阻、暂缓或目录边界不足时保持未完成。预算或数量达到可交阶段结果，但不自动进入下一市场。市场完成须有与声明范围相符的真实目录／分区边界和逐商户处理依据，公开资料不足就保留实际限制。

低产分别判断市场适配、入口未展开、历史重复、访问受阻或关键缺证。改用同市场真实可读路线；只有实读证据提示需要复核范围时才用review_required提前交接，状态不表示无客户或完成。用户明确调整市场范围才另建调整任务。默认80次／45分钟是上限，不是必须用完的指标。

## 6. 写回一张总表

按稳定ID准备当前分类、旧值、新值及理由。保留历史资格、原始来源、联系和人工记录；历史交付不覆盖。目录观察留后台且能回查，不删除历史主体。JSON的相关储备用candidate及有据channel_fit保存；单表导出显示“渠道储备”，不增加main数。Excel按原字段和当前分类记录更新。

写前核hash并备份，单一写入者合并，回读后更新活动索引及最新交付位置。只交一个Excel、一个客户总表，国家、城市、市场关系、客户类型、分类、产品、白牌、联系、来源、缺口、下一步与人工记录同排；不另拆品牌店或市场文件。

员工收到文件和实际结果：新增正式主体、旧线索晋级、相关储备／待核及必要限制。累计行数、目录观察和联系增量不当新增客户。当前市场未完成要写清，不把保存文件成功当成采集充分。

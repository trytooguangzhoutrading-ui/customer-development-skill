# 客户自动采集

员工描述需求后，自主研究、筛选、保存并交付Excel。使用当前Codex已有或已连接工具；Python脚本只处理本地数据，不联网、不调用独立AI API，不安装网站或常驻服务。

## 员工使用与范围

- 无需每次说技能名。提供简短状态、市场客户Excel和地区进度总览，内部查询、JSON和逐页日志留本地。宿主工具卡、强制进度与权限界面无法由技能隐藏。
- 新窗口先定位项目绑定、有效规则、公司配置和历史库，不能因没有聊天历史重新初始化空库。按[persistence.md](references/persistence.md)接续；首次绑定见[project-context.md](references/project-context.md)。已有信息不让员工重填。
- 默认主营智能眼镜、智能手表、智能手表表带、智能手环、智能戒指。蓝牙耳机、蓝牙音响（音箱同义）仅同渠道附带，不占主营合格数，不另开音频路线。五类主营不自行设权重或配额；员工明确指定产品时按专项执行。
- 独立商户只要有本轮目标产品经营证据，并通过主体、地域、买家角色、实际联系及去重门槛，即可进入可开发客户。白牌只作“已核／待核”标记，不作默认准入条件。“已核”只表示本任务至少一项产品白牌已有证据；尚无足够白牌证据标“待核”。若目前所读仅见品牌商品，另记实际所见，不能从“未见”写成“不存在”。
- 官方品牌店、品牌专卖店照常采集，满足其他门槛后放入独立的“品牌店”工作表，不混入独立商户。纯品牌方仍排除。不能只凭店名或Logo判断身份。
- 智能手表表带须有独立销售和智能表适配证据；兼容Apple Watch等不证明原厂、品牌店或白牌。普通眼镜、传统腕表、饰品戒指、被动音箱不冒充目标产品。功能、价格、MOQ及供货能力未知时留未知。
- 本次明确要求优先，其次项目有效规则和配置，再到技能默认。旧任务的white_label_required等原政策和交付保留；采用本次新规则时建立新任务，不静默重写旧资格。
- 只负责发现、研究和交接，不发送邮件、私信、询盘、电话，不处理报价、订单或销售跟进。安装不启动定时采集。

## 按顺序执行

1. **接续主库并确定范围。** 读取项目绑定、主表、全部补充查重源、人工备注及未结问题。首次读[business-rules.md](references/business-rules.md)与[customer-profile.md](references/customer-profile.md)。保存地区、主线及附带产品、买家类型、规则和基线；无历史数据才初始化。默认优先批发商、进口商、分销商及市场商户，再相关零售和电商。
2. **先建立地区和市场目录。** 按国家→城市／地区→批发市场／批发城→场内商户组织。先按[local-ecosystem.md](references/local-ecosystem.md)完成当地六类渠道初查与联系生态，记录相关市场的真实名称、范围、入口、规模依据和顺序。未知规模不猜；不能用几个独立站替代地区预研，也不把目录样例当完整市场名单。
3. **一次采完一个市场，再进入下一个。** 选定当前市场后，沿真实分区、楼层、街段、分页和商户清单逐一展开。先保存具名候选，再补主体、产品、位置和联系。当前市场仍有未读、受阻或暂缓路线时保留未完成，不自动跳到第二市场。可并行处理同一市场内不同分区或来源，统一主库只允许一个写入者。线上和第三方资料用于核当前市场商户，市场外对象单列地区补充，不能冒充场内或抢占当前市场。方法见[collection-playbook.md](references/collection-playbook.md)。
4. **逐主体查重并分表。** 对照所有历史状态、补充来源和本批候选，按经营主体、归属域名、完整业务联系、卖家ID及明确关系核同一商户。换店名、换产品、新分店和补电话不算新主体。独立商户核主营及其他准入；品牌店核身份后独立列示；纯品牌方排除。白牌证据单独记录，白牌待核不阻塞其他条件已满足的客户；主体、地域、产品、角色或联系归属冲突仍须待核。
5. **补齐可交接联系和业务依据。** 有电话只是下限，继续读取已见商户联系页、当地常用消息入口及官方自链。核显示号码和实际链接、用途及归属。电话不推Zalo／WhatsApp，客服不写成采购人，看到入口不表示已试联。经营能力、近期活动和供货适配按实际证据保存。
6. **保存并按市场交付。** 全部准入通过才分A/B；A另需经营能力及有效时间窗内带日期的活动证据。逐条预检、保存真实停止原因、提交并导出。每个市场单独Excel，包含可开发客户、品牌店、待核线索、来源证据和采集说明；另给地区／市场进度总览。分别统计独立商户、品牌店、新增主体、历史更新和待核，不把分表行数相加冒充净新增。回读后登记交付，旧交付冻结。

地区方法按需读[regional-profiles.md](references/regional-profiles.md)。全球任务逐国家、城市和市场推进，范围不一次铺满。没有可靠市场目录时先补目录；若已证实不适用，明确说明并按用户指定的其他渠道研究，不编造市场。

## 进度与结束

默认20个新增合格主体是阶段观察目标，不是市场完成条件。员工明确数量时可以达到数量后交阶段表；当前市场未读边界仍保留未完成。默认每轮最多80次尝试或45分钟，可由本轮需求覆盖。预算用尽、访问受阻、产出低或暂缓都不能把当前市场标完成，也不能自动切换下一市场。

市场完成必须有实际可核的目录／分区边界、已逐一处理的商户及没有剩余未读或受阻入口的记录。公开资料无法支持全场覆盖时只写实际已覆盖范围，不能用“网上能搜到的已读完”宣称整场采完。地区总览保留当前市场、未完成原因、下一入口和后续市场队列；只有当前市场完成才推进下一市场。

每次研究前登记实际查询／URL或已见链接动作，通过次数、时间、顺序和重试检查后才联网。读取后保存来源、候选和尝试，分段checkpoint。先prepare有效子集，再research finish、commit、export和回读；精确契约见[research-progress.md](references/research-progress.md)。脚本只校验声明，Codex仍须实际读取。

“继续”按持久任务索引恢复当前市场、已读边界、未读入口、预算和问题；未提交恢复同一草稿，已提交建立接续批。JSON用workflow CLI，Excel按project-context.md维护独立索引和日志。仅补指定名单用enrich，无需重做全城地图；没有新条件不循环重试失败路径。

接续时比较公司配置与原任务范围。仅继续原任务保留原政策；用户明确采用新产品或本次商户规则时新建任务并沿用历史查重、适用预研和未结问题。安装新版本不会自动同步公司配置。维护或验收按[真实业务验收](references/business-acceptance.md)记录结果，程序测试不代替业务效果。

## 事实与交付边界

- 未写品牌、无Logo、低价或通用型号不证明白牌；白牌、OEM服务、接受我方供货分别核实。白牌资料冲突只影响白牌标记；若同时涉及主体、目标产品或其他准入事实，相关资格仍待核。
- 商户、运营公司、品牌、市场管理方、平台客服与联系人分开。平台共域／同名只是弱关联，不能合并整个平台卖家或借管理处号码。
- 官网首页、地址、无消息入口的展示主页不能满足联系门槛；残缺号码不猜。历史沿用保留原核验日期，不冒充本轮现用或试联成功。
- 送货范围不是经营地点，同城不是场内。行政地名变化按官方资料映射并保留原址。公司级批发、SKU批发、库存、MOQ分开；读取日期不代替活动日期。
- 搜索摘要、当前原文、第三方、历史缓存与读取失败分层。登录墙、验证码、JS壳不当正文。只用正常公开或已授权资料，不绕保护、不自行购买数据。

脚本路径相对本SKILL.md解析，Python 3.9+标准库即可。运行前读[data-contract.md](references/data-contract.md)。数据留用户项目，不写入技能安装目录或开源包；已有Excel继续作主库，不为CLI另造空JSON库。市场Excel是交付视图，所有市场共用主库和跨表查重。

保留稳定ID、实际产品、白牌标记及核验说明、首选入口、市场位置和缺口。附带音频在待核表写“附带拓展／主线范围外”。号码／ID按文本保存，不输出undefined、猜测日期或CSV改扩展名。回读工作表、数量、来源和联系方式；有渲染能力再检查显示。没有联网能力时只整理已有资料并注明限制，零结果也据实交付。
